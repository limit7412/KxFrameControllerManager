# 27062 のメッセージ

ヘッドセット内の SteamVR ウェブサーバー（`127.0.0.1:27062`）へ送る切断要求と、返ってくる一覧の形式である。
非公開のプロトコルであり、SteamVR の更新で変わりうる。
実装は `src/frame_link/` にある。

| 項目 | 値 |
| --- | --- |
| 確かめた日 | 2026-11-09 |
| SteamOS | SteamOS VR 0.4.5（BUILD 20261022.6150929） |
| 確かめた内容 | 左コントローラーへの切断要求 1 回で LED が消え、VR 空間からも消えた。ボタンで再びつながった |

## 参照

形式は OyasumiVR の文書（`feature/steam-frame-support` ブランチの [steam-frame-pairing.md](https://github.com/Raphiiko/OyasumiVR/blob/feature/steam-frame-support/docs/agents/steam-frame-pairing.md)）を一次情報とし、実機の通信と照合した。
OyasumiVR のコードは使っておらず、文書に書かれた手順だけを参照している。

## 接続

1. `ws://127.0.0.1:27062/` へ `Origin: http://127.0.0.1:27062` を付けてつなぐ。同じサーバーを Origin にすると、Web シークレットを求められない
2. テキスト `steam_connect` を送る
3. 下のバイナリを送る

接続は要求のたびに張り、終わったら閉じる。
localhost からしか届かないため、要求を出すプロセスはヘッドセット上で動かす。

## バイナリの形

メッセージは「ヘッダの長さ（varint）、ヘッダ、本体」の並びである。
ヘッダと本体はどちらも protobuf の形式で、ヘッダの field1 が種別を表す。
`02 08 2d …` は、長さ 2 のヘッダ `08 2d`（field1 = 45）に本体が続いたものである。

| 方向 | 種別 | バイト列 | 意味 |
| --- | --- | --- | --- |
| 送信 | 45 | `02 08 2d 0a 00` | 一覧の要求。本体は空の field1（update） |
| 送信 | 45 | `02 08 2d 2a 0e 0a 0c` + シリアル 12 バイト | 切断要求。本体の field5（disconnect_controller）の中の field1 にシリアル |
| 受信 | 44 | `02 08 2c` + 本体 | 一覧。field3 が接続中、field4 がペアリング済み |
| 受信 | 46 | `02 08 2e` + 本体 | コントローラーごとの状態。中身は未解明 |
| 受信 | 33 | `02 08 21` + 本体 | 用途は未解明 |

種別 44 の要素は、どちらも field1 がシリアルである。
接続中（field3）の要素の field2 は、1 が左、2 が右を表す。

切断要求の直後に種別 44 が届き、切ったコントローラーは接続中から外れてペアリング済みにだけ残った。
本ツールはこれを切断の確認にも使う。

## シリアルの対応

OpenVR の `Prop_SerialNumber_String` から先頭の `cv.` を外したものが、27062 のシリアルと一致した。

| 手 | OpenVR | 27062 |
| --- | --- | --- |
| 左 | `cv.91481bedcdfa` | `91481bedcdfa` |
| 右 | `cv.5dd5caddfde0` | `5dd5caddfde0` |

この変換で一致しなければ切らない。

## 壊れたときに見るもの

`log_level` を `debug` にすると、送受信したバイナリが 16 進表記でログに出る。
上の表と食い違うところが、更新で変わったところである。
